# Security and health-content safety

This is a static educational app, not a clinical record system. Health logs are optional localStorage records, not encrypted or remotely backed up. Anyone with access to the same browser profile may read them. Do not submit health data in public issues.

Report reproducible code vulnerabilities with a minimal synthetic case. Repository maintainers should enable GitHub private vulnerability reporting before soliciting sensitive reports; no maintainer contact address is invented in this template. Medical-content corrections can use the evidence issue template without personal details.

Preserve HTML escaping, HTTPS-only source URLs, CSV formula defenses and fail-closed recommendation gating. New user-upload or remote-content features require a new threat review. Do not execute script/foreignObject/remote references from SVGs.

Current test coverage does not constitute penetration testing, clinical validation or regulatory approval. Data integrity failures, unsafe suggestions and misleading source attribution are release-blocking defects, not merely UI polish.
