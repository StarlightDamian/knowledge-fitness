# 新增器材：最小可审核改动

## 同一个主类内新增类型

复制一个相近的`src/data/equipment/*.json`，修改文件名与稳定ID，填写`zh-CN`和`en`名称、用途、注意事项、证据范围。补常见别名，按[TAXONOMY](TAXONOMY.md)选唯一主类，其他属性用标签。

不要把模板里的用途/注意事项原封不动复制成“适合全身/注意安全”。每个条目至少应有一个区别于邻近类型的结构或使用特征。

必须检查 `sources` 文档ID存在，明确它支持训练类别、产品结构还是直接比较。没有具体型号手册时，保留 `model-specific review pending`，不要编造尺寸、最大负载、价格、风险或疗效。

可以复用主类SVG；它只能标为类别示意。新增图像需要来源与许可，不把网络图片地址当授权。新增主类则还要更新`categories.json`、Schema枚举、图像资源、分类文档与测试。

```bash
npm run check
```

构建自动发现新JSON，更新搜索、比较表、导出、器材勾选器和计数。不必手改HTML。代码校验引用完整性和基本字段；这不代替专业审阅。提交源JSON与生成后的根目录/dist HTML。

## 让已有动作接受新器材

仅新增器材不会自动证明它能替换某动作。到`src/data/exercises.json`逐个审核：

```json
{
  "equipmentOptions": [
    ["dumbbell"],
    ["adjustable-dumbbell"]
  ]
}
```

以上表示固定哑铃或可调哑铃满足该动作的设备条件，仍需足够的可用负荷与正确设置。内层多个ID表示必须全部具备，不能只满足其中一个。迷你带不自动视为长环带，训练凳不自动视为可靠保护装置。

新增计划要显式列出全部课次、动作、组次、余力、休息、热身、进阶、退出条件和局限。不要把“器材可用”解释成“用户能安全完成”。

## 审查清单

ID/文件名一致；主类和标签有效；中英正文齐全；不重复品牌变体；用途和注意事项独特；来源与作用对应；替代方向不是医疗等效；资源文件存在且无恶意SVG；Schema/验证器/测试通过；网页可搜索并加入比较；计划资源映射未偷换；覆盖率不随新增数量自动宣称达标。

完整字段定义见`schemas/equipment.schema.json`。仓库中的`src/validate.mjs`是无依赖的字段/引用检查器，不是完整JSON Schema解释器；编辑器可额外使用支持2020-12规范的Schema工具。
